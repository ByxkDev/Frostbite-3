# ⚠️ Work In Progress

This project is an experimental implementation of a replacement backend for **Battlefield 4 (PlayStation 3)**.

The primary goal is to recreate the required EA backend infrastructure so that the original Battlefield 4 PS3 client can communicate with a custom server **without modifying the game executable**.

The emulator currently provides:

* DNS-based redirection
* A TLS-enabled GOS Redirector endpoint
* A Blaze TCP game server
* Blaze packet parsing
* TDF parsing
* Component-based request handling
* Custom certificate generation
* Legacy TLS compatibility

The major TLS compatibility blocker has now been resolved.

The original Battlefield 4 PS3 client can successfully complete the TLS handshake with the custom server using the certificate generated by the included `generate.bat` script.

Development is now focused on the protocol traffic that occurs after the successful TLS connection.

# TLS Status

The Battlefield 4 PS3 client successfully:

* Connects to the custom redirector.
* Sends a TLS ClientHello.
* Negotiates a compatible legacy TLS configuration.
* Accepts the generated certificate.
* Completes the TLS handshake.
* Continues to the application protocol.

The emulator supports the legacy RSA cipher suites required by the PS3 client.

Current TLS configuration includes:

```text
TLS 1.0 - TLS 1.2

TLS_RSA_WITH_AES_128_CBC_SHA
TLS_RSA_WITH_AES_256_CBC_SHA
```

The TLS implementation is designed around the limitations of EA's legacy **ProtoSSL** implementation used by Battlefield 4 PS3.

# Certificate Generation

The repository contains the certificate generation tools required for the PS3 TLS connection.

Certificate files are located under:

```text
network/certificates/
```

The server expects:

```text
network/certificates/gosredirector.pfx
```

**The certificate is not included in this repo, use the Bug_OldProtoSSL guide from Aim4Kill's github**

The certificate is loaded from the PFX file at runtime.

The server extracts the certificate and RSA private key using PowerShell and converts them into the format required by Go's TLS implementation.

# DNS Redirection

The original game connects to:

```text
gosredirector.ea.com
```

DNS is used to redirect the hostname to the emulator server.

Example:

```text
gosredirector.ea.com -> 151.xxx.xxx.xx
```

The original hostname is preserved so that the PS3 client can continue communicating using the expected EA endpoint.

No EBOOT modification is required for the DNS redirection itself.

# Server Architecture

The emulator currently consists of two primary TCP services.

## GOS Redirector

```text
Hostname:
gosredirector.ea.com

Port:
42127

Protocol:
TLS/TCP
```

The redirector uses:

```text
network/certificates/gosredirector.pfx
```

The server loads the PFX certificate and starts a TLS listener.

Connections are passed into the Blaze packet handler after the TLS layer has been established.

---

## Blaze Server

```text
IP:
151.xxx.xxx.xx

Port:
33152

Protocol:
TCP
```

The Blaze server uses a normal TCP listener.

Unlike the redirector, the current server listener does not use TLS.

Incoming connections are passed directly to the Blaze packet handler.

# Blaze Protocol

The emulator implements portions of EA's Blaze networking protocol.

Incoming TCP data is passed to the Blaze component handler:

```go
reply := components.HandlePacket(data)
```

The general packet flow is:

```text
PS3 Client
    |
    | TCP
    v
Server
    |
    v
Blaze Packet Parser
    |
    v
TDF Decoder
    |
    v
Component Handler
    |
    v
Response Builder
    |
    v
PS3 Client
```

The server currently receives complete TCP reads and passes the received data to:

```go
components.HandlePacket()
```

Responses generated by the component handler are written directly back to the client.

# TLS / ProtoSSL Research

Battlefield 4 PS3 uses EA's legacy **ProtoSSL** implementation.

The client advertises legacy RSA cipher suites that are no longer commonly used by modern TLS implementations.

Research for this project has focused on:

* Legacy RSA cipher suites
* TLS version compatibility
* Certificate chain compatibility
* RSA certificate compatibility
* Signature compatibility
* ProtoSSL behavior
* PS3 TLS limitations
* EA certificate structures
* OpenSSL compatibility
* Go TLS compatibility

The TLS handshake is now successfully completed by the original PS3 client.

The project can therefore move beyond the TLS negotiation stage and begin analyzing the application traffic generated afterwards.

# Client Analysis

Development relies heavily on information extracted from the original Battlefield 4 PlayStation 3 client.

A `strings.txt` file can be generated from the original `EBOOT.ELF`.

These strings help identify:

* Domains
* URLs
* Blaze components
* Service names
* Redirect endpoints
* Internal protocol identifiers
* Configuration values

This information is combined with:

* Packet captures
* TLS debugging
* Server logs
* PS3 client logs
* Protocol analysis

to reproduce the behavior expected by the original client.
